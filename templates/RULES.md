# 書き方のルール

このフォルダのタスクを読み書きするときのルールです。人、AI、アプリのすべてがこのルールに従います。

**AIへ：このフォルダのファイルを編集する前に、必ずこのファイルを最後まで読んでください。**

## フォルダ構成

```
tasks/
├── RULES.md          このファイル
├── TEMPLATE.md       新規チケットのテンプレート
├── NOTE_TEMPLATE.md  新規ノートのテンプレート
├── CLAUDE.md         AI向けの案内（このファイルを読むように書いてあるだけ）
├── AGENTS.md         同上
├── TAGS.md           タグの色（アプリが書く。人やAIは書き換えなくてよい）
├── tickets/          チケット（1チケット＝1ファイル）
├── archive/          アーカイブした（片付けた）完了済みのチケット
└── notes/            ノート（議事メモなど。1ノート＝1ファイル）
```

## チケットの形

1つのチケットは、1つのmdファイルです。先頭の `---` で囲んだ部分（frontmatter）に管理用の項目を書き、その下の本文にタイトルとメモを書きます。

```markdown
---
id: 20261018-1356-k3x9
status: todo
priority: 2
start:
due: 2026-10-22
repeat:
tags: [仕事]
parent:
source:
assignee:
author:
created: 2026-10-18
done:
---

# 見積書を送る

## メモ
- 金額は前回と同じでいいか確認する
```

- タイトルは本文の先頭に `# 見出し` で書きます。
- 日付も状態も要らない小さな作業は、本文にチェックボックス（`- [ ]`）で書きます。
- 自分の期限や状態が要る作業は子チケットにして、`parent` に親のIDを書きます。

## frontmatterの項目

ここにある項目だけを、この順番で書きます。値がない項目も、行は消さずに空のまま残します。

| 項目 | 必須 | 書き方 | 意味 |
| --- | --- | --- | --- |
| `id` | 必須 | `YYYYMMDD-HHMM-xxxx` | チケットのID（下の「ID」を参照） |
| `status` | 必須 | `todo` / `doing` / `waiting` / `done` | 状態。`waiting` は返事待ち・保留 |
| `priority` | 任意 | `1` / `2` / `3` | 優先度。1が高く、3が低い。迷ったら `2` |
| `start` | 任意 | `YYYY-MM-DD` | 着手日 |
| `due` | 任意 | `YYYY-MM-DD` | 期限 |
| `repeat` | 任意 | 下の「繰り返し」を参照 | 繰り返しの規則 |
| `tags` | 任意 | `[タグ1, タグ2]` | 分類用のタグ |
| `parent` | 任意 | 親チケットのID | 親チケット。子の側にだけ書く |
| `source` | 任意 | ノートのID | このチケットを起こした元のノート（議事メモなど）。チケットの側にだけ書く |
| `assignee` | 任意 | 担当者の名前。2人以上は `[高橋, 田中]` | 担当者。1人なら名前だけ、2人以上ならリストで書く |
| `author` | 任意 | 作成者の名前 | 作成者。アプリは作るときに設定の「自分の名前」を入れる |
| `created` | 必須 | `YYYY-MM-DD` | 作成日 |
| `done` | 任意 | `YYYY-MM-DD` | 完了日 |

## ID

- 形式は `YYYYMMDD-HHMM-xxxx` です。作成した日時（現地時刻、分まで）と、英小文字と数字からなるランダムな4文字をつなげます。例：`20261018-1356-k3x9`
- チケットとノートは同じ形式のIDを使います。新しく作るときは、`tickets/`・`archive/`・`notes/` のどれにも同じIDのファイルがないことを確かめてください。

## ファイル名

- チケットは `tickets/`、ノートは `notes/` の中に、`ID.md` か `ID_好きな文字.md` の名前で置きます。例：`20261018-1356-k3x9.md`、`20261018-1356-k3x9_見積書を送る.md`
- `_` から後ろは自由に付け足し・変更して構いません。正式なタイトルは本文の見出しです。
- 新しく作るときは `ID.md` のままで構いません。アプリは起動したときに、`ID.md` のファイルに見出しを付け足すことがあります（`ID_見出し.md`）。
- ファイル名に `\ / : * ? " < > |` は使えません。タイトル部分は40文字までにします。
- ファイル名の先頭のIDと、frontmatterの `id` は必ず同じにします。

## 書き方の決まり

- 文字コードはUTF-8（BOMなし）、改行はLFです。
- 日付はすべて `YYYY-MM-DD` で書きます。
- 他のチケットやノートに触れるときは、標準の md のリンクで書きます。リンク先は、今のファイル名を相対パスで書きます（同じフォルダならファイル名だけ、違うフォルダなら `../notes/` などを付ける）。例：`[A社定例](../notes/20261015-1400-mt01_A社定例.md) の続き`
  - アプリはリンク先のファイル名の先頭の ID だけで探すので、ファイル名が変わったり `archive/` に移ったりしても開けます（ほかのエディタではたどれなくなることがあります）。
  - ID だけを文字で書いても構いません。例：`20261015-0930-p2m7 の続き`

### 正式な書き方

| 要素 | 書き方 |
| --- | --- |
| 見出し | `#` を使う（下線形式は使わない） |
| 箇条書き | `-` |
| 番号付きリスト | `1.` |
| チェックボックス | `- [ ]` と `- [x]` の2種類だけ |
| 太字 / 斜体 | `**太字**` / `*斜体*` |
| 取り消し線 | `~~取り消し線~~` |
| リンク | `[テキスト](URL または相対パス)` |
| コードブロック | バッククォート3つ |

表は次の形で書きます。列の幅は揃えません（空白や `-` を足して縦をそろえない）。区切り行は `---` で、揃えるときだけ `:---`（左）、`:---:`（中央）、`---:`（右）にします。

```markdown
| 項目 | 金額 |
| --- | ---: |
| 見積 | 1,000円 |
```

### 使わない記法

特定のツールでしか意味を持たない記法は使いません。

- `[[リンク]]`、`![[埋め込み]]`
- `> [!note]` のようなコールアウト
- `==ハイライト==`、`%%コメント%%`
- `📅 2026-10-20` のような絵文字での日付指定
- `項目:: 値` のようなDataviewの項目やクエリ
- `- [-]` や `- [/]` のような独自のチェック状態

## 繰り返し

| 書き方 | 意味 |
| --- | --- |
| `daily` | 毎日 |
| `weekdays` | 平日（月〜金） |
| `weekly:mon` | 毎週月曜（`mon` `tue` `wed` `thu` `fri` `sat` `sun`） |
| `weekly:mon,thu` | 毎週月曜と木曜（曜日は `,` でつなぎ、空白は入れない） |
| `monthly:25` | 毎月25日（その月にない日は月末） |
| `monthly:end` | 毎月末 |
| `monthly:2tue` | 毎月第2火曜（`1`〜`4` と曜日） |
| `monthly:lastfri` | 毎月最終金曜 |
| `yearly:12-25` | 毎年12月25日（`MM-DD`。`02-29` はうるう年でない年は2月28日） |
| `every:2w` | 2週ごと（`d` 日、`w` 週、`m` 月。元の予定から数える） |
| `after:7d` | 完了した日から7日後（`d` 日、`w` 週、`m` 月） |

`after:` 以外は、完了が遅れても次回の日付は変わりません。英字は小文字で書きます。

## 完了にするとき

1. `status: done` にして、`done` に今日の日付を入れます。
2. `repeat` がある場合は、次回分のチケットを新しいIDで作ります。
   - タイトル、`tags`、`priority`、`repeat`、`parent`、`assignee` を引き継ぎます。本文のメモは引き継ぎません。
   - `start` がある場合は、次回の `start` を `repeat` の規則から計算し、`due` は元の `start` から `due` までの日数を保ってずらします（例：毎月最終木曜に始めて翌日が期限の作業は、次回も最終木曜に始まる）。
   - `start` がない場合は、次回の `due` を `repeat` の規則から計算します。どちらもない場合は、完了した日から数えた日を `due` にします。
   - 次回分を作るのは、完了にした人（またはAI）だけです。
   - 完了を取り消しても、作った次回分は消しません。もう一度完了にしたときに、同じ次回分（タイトル・繰り返し・親・日付が同じ）がすでにあれば作りません。
3. 完了したチケットは削除せずに残します。片付けるときは、ファイルを `archive/` に移します（アーカイブ）。

## アーカイブと削除

- アーカイブするのは、完了したチケットだけです。子チケットがあるときは、子孫もすべて完了していれば一緒に `archive/` に移します。未完了の子孫があるうちは移しません。
- 移すときは、ファイル名も中身も変えません。親子は ID でつながっているので、`tickets/` と `archive/` に分かれても切れません。
- `archive/` のチケットも、同じ書き方のルールに従います。戻すときは `tickets/` に移します。
- 間違って作った・要らなくなったチケットは、削除して構いません。アプリは OS のごみ箱に移します（子チケットも一緒に）。完全に消すのは人が行います。

## 親子関係

- 子チケットの `parent` に親のIDを書きます。親の側には何も書きません。
- 孫やひ孫も同じ書き方です。深さに制限はありません。
- お互いを親にする（循環する）書き方はしないでください。
- 親チケットの `start` / `due` は任意です。書く場合は「親としての締切」の意味になります。

## ノート

チケットにならない情報（議事メモ、調べたこと、決めたことなど）は、ノートとして `notes/` に置きます。ID・ファイル名・タイトル（本文先頭の `# 見出し`）の決まりは、チケットと同じです。新しいノートは `NOTE_TEMPLATE.md` をもとに作ります。

```markdown
---
id: 20261019-1400-m3k8
date: 2026-10-19
tags: [A社]
author:
created: 2026-10-19
---

# A社定例

## 要点

## 決定事項

## 宿題
- 見積書を送る（高橋） → [20261019-1512-x7q2](../tickets/20261019-1512-x7q2_見積書を送る.md)

## 文字起こし
（会議の文字起こしをそのまま貼る）
```

ノートの frontmatter には、次の項目だけを、この順番で書きます。値がない項目も、行は消さずに空のまま残します。

| 項目 | 必須 | 書き方 | 意味 |
| --- | --- | --- | --- |
| `id` | 必須 | `YYYYMMDD-HHMM-xxxx` | ノートのID |
| `date` | 任意 | `YYYY-MM-DD` | 会議などの日。「来週金曜」などを日付にするときの基準 |
| `tags` | 任意 | `[タグ1, タグ2]` | 分類用のタグ（プロジェクトなど） |
| `author` | 任意 | 作成者の名前 | 作成者 |
| `created` | 必須 | `YYYY-MM-DD` | 作成日 |

- 見出し（要点・決定事項・宿題・文字起こし）は目安です。要らないものは消して構いません。
- 「文字起こし」の下には、原文をそのまま貼ります。整えたり要約で置き換えたりしません。起こしたタスクが正しいかを、後から確かめるためです。

## 議事メモからタスクを起こす

ノート（議事メモ）からチケットを起こすときは、次の順に進めます。

1. **候補を出す**：ノートを読み、タスクの候補を一覧で出します。各候補には、タイトル、担当者、期限、根拠になった発言（文字起こしの該当箇所）を付けます。担当者が2人以上なら、全員を `assignee: [高橋, 田中]` の形で書きます。
   - 「来週金曜」などの期限は、ノートの `date` を基準に `YYYY-MM-DD` にします。`date` が空なら `created` を基準にし、そのことを伝えます。
   - 期限や担当者がはっきりしないものは、空のまま候補に出します。推測で埋めません。
   - 雑談や「検討します」のような、やることが決まっていない発言は候補にしません。迷うものは、迷っていると書いて出します。
2. **人が選ぶ**：候補を出したら、どれを作るかを人に確かめます。**確かめる前にチケットを作ってはいけません。**
3. **チケットを作る**：選ばれた候補を、`TEMPLATE.md` をもとにチケットにします。ファイル名は `ID_タイトル.md` にします（宿題に書くリンクが、後で名前を変えても切れないように）。
   - `source` にノートのIDを入れます。
   - `tags` は、ノートの `tags` を引き継ぎます（人が別のタグを指定したらそれに従う）。
   - 本文の「メモ」に、根拠になった発言を短く書きます。
4. **ノートに書き戻す**：ノートの「宿題」の該当する行の最後に、作ったチケットへのリンク ` → [ID](../tickets/ファイル名)` を足します。ファイル名に空白や括弧があるときは、リンク先を `<…>` で囲みます（例：`- 見積書を送る（高橋） → [20261019-1512-x7q2](../tickets/20261019-1512-x7q2_見積書を送る.md)`）。
   - 「宿題」に該当する行がなければ、行を足します。「宿題」の見出しがなければ、「文字起こし」の見出しの前（なければ本文の最後）に足します。
   - 書き換えるのは「宿題」だけです。ほかの部分、とくに「文字起こし」には触れません。
5. **二重に作らない**：同じノートでもう一度頼まれたときは、`tickets/` と `archive/` から `source` がそのノートのIDのチケットを先に探し、すでにあるタスクは候補から外します。

起こしたチケットとのつながりは、チケットの `source` が正です。「宿題」に書くリンクは、人が読むときにわかりやすくするためのものです（前の版の `→ ID` の書き方も、そのまま使えます）。

頼まれたら、「要点」「決定事項」も文字起こしからまとめて書きます。

## AIへのお願い

- 頼まれたチケットと項目以外は変更しないでください。関係のない行の書式を整えることもしないでください。
- 新しいチケットは `TEMPLATE.md`、新しいノートは `NOTE_TEMPLATE.md` をもとに作ってください。
- このルールにない項目や記法が必要になったら、使う前に人に確認してください。
