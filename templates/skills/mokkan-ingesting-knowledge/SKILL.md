# 記録を知識に取り込む

記録のノートからわかったことや決まったことを、知識のノートに「今の正しい状態」として取り込む手順です。知識のノートと入口のノートの書き方は、`RULES.md` の「ノートの書き方」にあります。まだ読んでいなければ、先に読みます。

この手順で使う言葉：

- **記録**：取り込む元の、`type: record` のノート
- **知識**：`type: knowledge` のノート
- **入口**：プロジェクトのフォルダの直下の `type: index` のノート
- **案**：知識や入口をどう書き換えるかの提案

## 進み具合

次のチェックリストを写し、進めながら印を付けます。

```
記録を知識に取り込む：
- [ ] 1. 記録・入口・関係する知識を読む
- [ ] 2. 案を出す
- [ ] 3. 人が選ぶ（選ぶまで書き換えない）
- [ ] 4. 書き換える
- [ ] 5. 書いた後に見直す
- [ ] 6. 伝える
```

## 1. 読む

- 記録と、そのプロジェクトの入口を読みます。入口の一覧の要約から、関係しそうな知識を選んで読みます。`notes/共通/` の知識も、関係しそうなものは読みます。
- 議事メモは「要点」「決定事項」を中心に読み、根拠は「文字起こし」と照らし合わせます。
- 知識に、この記録へのリンクがすでにあれば、その部分は取り込み済みです。

## 2. 案を出す

知識ごとに、次のどれかを一覧で出します。**どの案にも必ず「根拠：」の行を付け**、記録のどの見出しのどの文か（引用）と、記録のノートへのリンクを書きます。入口を直す案も同じです（どの記録から分かったことかを書く）。

- **書き換える**：今の記述と、新しい記述
- **新しく作る**：使うテンプレート（`templates/notes/` の手順・参照・解説）、置くフォルダ、タイトル、1〜3行の要約
- **入口を直す**：一覧に足す・消す・書き換える行と、「知識の状況」の書き換え。入口がなければ、作る案（作り方は `mokkan-writing-project-indexes` と同じ）
- **チケットの案**：作業が終わった・新しい作業が出たなど、進み具合の話は知識にも入口にも書かず、チケットを作る・直す案として出します

決まり：

- そのプロジェクトだけの決まりは、プロジェクトのフォルダの知識に書きます。`notes/共通/` には、プロジェクトをまたいで当てはまることだけを書きます。
- 知識にしないもの（その場かぎりの話、決まっていないこと、一度きりの作業）は出しません。迷うものは、迷っている理由を書いて出します。
- 記録が今の知識と食い違うときは、記録の `date` と知識の `reviewed` を添えて、どちらが新しいかがわかるように出します。

案は次の形で出します。

```
■ notes/案件A/20261001-0900-k1a2_見積の決まり.md（書き換える）
  今：見積は税抜で出す
  新：見積は税込で出す（[A社定例](20261019-1400-m3k8_A社定例.md) で決定）
  根拠：A社定例の決定事項「今後の見積は税込表記にする」（記録の date 2026-10-19／知識の reviewed 2026-09-30）
■ 新しく作る：notes/案件A/（テンプレート：手順）
  タイトル：見積書の送り方
  要約：見積書を PDF にして、担当者に送り、共有フォルダに置く手順。
  新しい記述：- 送った見積書は共有フォルダの「見積」に置く（[A社定例](20261019-1400-m3k8_A社定例.md) で決定）
  根拠：A社定例の要点「送った見積は共有フォルダに置く」
■ 入口（一覧の行を足す）
  - [見積書の送り方](ID_見積書の送り方.md)：見積書の送り方と置き場所
  根拠：上の「新しく作る」に合わせる
```

新しく作る案には、テンプレート（手順・参照・解説のどれか）・置くフォルダ・タイトル・1〜3行の要約を必ず入れます。

## 3. 人が選ぶ

どの案を反映するかを人に確かめます。**確かめる前に知識や入口を書き換えてはいけません。**

## 4. 書き換える

選ばれた案だけを、`RULES.md` の「ノートの書き方」に従って反映します。

- 書き足さずに書き換え、経緯は書きません。取り込んだ記述ごとに、根拠として記録へのリンクを置きます（取り込み済みかの目印にもなる）。
- 記録の中の「来月から」「今月中」などは、記録の `date` を基準に日付（`YYYY-MM-DD` か `YYYY-MM`）にして書きます。
- 書き換えた知識と新しく作った知識の `reviewed` を今日にします。
- 記録は書き換えません（取り込み済みの印も付けません）。

## 5. 書いた後に見直す

書き換えたノートごとに、次を見直します。違っていたら直してから、もう一度見直します。

- 知識に「以前は〜」などの経緯が入っていない
- 取り込んだ記述に、根拠の記録へのリンクがあり、相対パスがそのファイルを指している
- `reviewed` が今日になっている
- 新しく作った知識が、入口の一覧に載っている

## 6. 伝える

書き換えたノートごとに、何を変えたかを1〜2行で人に伝えます。
