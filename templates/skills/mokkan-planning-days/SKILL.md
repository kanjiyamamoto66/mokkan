# 時間割を組む

その日の時間割を、`days/YYYY-MM-DD.md` に組む手順です。時間割のファイルの形と、いつもの予定（`days/routine.md`）の書き方は `RULES.md` の「時間割」にあります。まだ読んでいなければ、先に読みます。

この手順で使う言葉：

- **時間割**：`days/YYYY-MM-DD.md`。その日の予定を1行ずつ書く
- **予定**：時間割の1行（`- 10:00-11:00 内容`）。チケットや議事メモへのリンクでも、ただの文字でもよい
- **まずやる候補**：期限がその日まで（期限切れを含む）か、`status: doing` のチケット
- **着手日を過ぎた候補**：それ以外で、着手日（`start`）がその日までのチケット。アプリで作ると着手日は作った日になるので多くなりやすい。空いた時間に置く
- どちらの候補にも入れないもの：完了（`done`）・待ち（`waiting`）・アーカイブしたもの・未完了の子チケットを持つ親（親の作業は子で置く。子がすべて完了した親は候補にする）
- **いつもの予定**：`days/routine.md` の繰り返しの予定
- **作業する時間**：`days/routine.md` の frontmatter の `work`。時間割はこの時間に収める

## 進み具合

次のチェックリストを写し、進めながら印を付けます。

```
時間割を組む：
- [ ] 1. 日付と、今の時間割・いつもの予定・候補を読む
- [ ] 2. 案を出す
- [ ] 3. 人が確かめる（確かめるまで書かない）
- [ ] 4. 書く
- [ ] 5. 書いた後に見直す
- [ ] 6. 伝える
```

## 1. 読む

- どの日かを決めます（「今日」「明日」などは、今日の日付から決める）。
- その日の時間割（`days/YYYY-MM-DD.md`）があれば読みます。すでにある予定は動かさず、空いている時間に置きます。
- 時間割がまだなく、その日が今日か先の日なら、`days/routine.md` からその日に当たる行を写す前提で考えます。
- `tickets/` から、まずやる候補と着手日を過ぎた候補を探し、`estimate`（所要時間）を見ます。`estimate` がないものは、所要時間を人に聞くか、30分として案に書きます（アプリの時間割の目安も30分で数える）。
- 作業する時間は、`days/routine.md` の frontmatter の `work`（例：`work: 09:00-18:00`）から読みます。人に聞く必要はありません。人がこの日だけの時間を言ったときは、そちらを使います。`work` がない・`routine.md` がないときは 9:00〜18:00 として、そのことを伝えます。
- 外のカレンダーの予定を取り込むように頼まれたら、使えるカレンダーの連携（MCP など）でその日の予定を読みます。使える連携がなければ、そう伝えて予定を教えてもらいます。

## 2. 案を出す

時刻の順に、予定の行をそのまま出します。

- チケットは、リンクで書きます：`- 10:00-11:30 [見積を作る](../tickets/20261124-1000-abcd_見積を作る.md)`
- MTG・昼休みなど、チケットでない予定は文字だけで書きます：`- 12:00-13:00 昼休み`
- 1つのチケットを、何回かに分けて置いて構いません（同じリンクの行を2つ書く）。
- まずやる候補を先に、その中では期限の近いもの・優先度の高いもの（`priority: 1`）を先に置きます。着手日を過ぎた候補は、空いた時間に置きます（全部を置こうとしない）。
- 作業する時間に入り切らないまずやる候補は、置かずに「入り切らない候補」として並べ、別の日にするか人に聞きます。
- 時刻は15分刻みにします。

例：

```
2026-11-24（火）の時間割の案（作業する時間 9:00〜18:00）：
- 09:00-09:15 朝会（いつもの予定）
- 09:15-10:45 [見積を作る](../tickets/20261124-1000-abcd_見積を作る.md)（期限 11/25、所要時間 1h30m）
- 11:00-12:00 定例MTG（いつもの予定）
- 12:00-13:00 昼休み
- 13:00-13:30 [請求書の送付](../tickets/20261120-0900-ef12_請求書の送付.md)（期限切れ、所要時間なし→30分）
入り切らない候補：[資料をまとめる](../tickets/…)（所要時間 4h）
```

## 3. 人が確かめる

案を人に確かめます。**確かめる前に時間割のファイルを作ったり書き換えたりしてはいけません。**

## 4. 書く

- 時間割がなければ、次の形で作ります。いつもの予定の当たる行も写します。

  ```markdown
  ---
  date: 2026-11-24
  ---

  - 09:00-09:15 朝会
  ```

- 時間割があれば、予定の行を時刻の順の位置に足します。ほかの行（メモなど）は変えません。
- リンク先の相対パスは、`days/` から見た形（`../tickets/…`・`../notes/…`）にします。

## 5. 書いた後に見直す

次を見直します。違っていたら直してから、もう一度見直します。

- どの予定の行も `- HH:MM-HH:MM 内容` の形で、終わりが始まりより後
- リンクの相対パスが、実際のチケットやノートのファイルを指している
- 書き足した行のほかに、もとからあった行が変わっていない
- frontmatter の `date` が、ファイル名の日付と同じ

## 6. 伝える

書いた予定と、入り切らなかった候補を人に伝えます。
