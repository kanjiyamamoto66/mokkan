# チケットを整理する

たまったチケットを見直し、今の状況に合うように直す手順です。チケットの項目と、完了・アーカイブの決まりは、`RULES.md` の「frontmatterの項目」「完了にするとき」「アーカイブと削除」「親子関係」の節にあります。まだ読んでいなければ、先に読みます。

この手順で使う言葉：

- **チケット**：`tickets/` の md
- **未完了**：`status` が `done` でないチケット
- **案**：チケットをどう直すかの提案

## 進み具合

次のチェックリストを写し、進めながら印を付けます。

```
チケットを整理する：
- [ ] 1. 範囲を決めて読む
- [ ] 2. 洗い出す
- [ ] 3. 案を出す
- [ ] 4. 人が選ぶ（選ぶまで書き換えない）
- [ ] 5. 書き換える
- [ ] 6. 書いた後に見直す
- [ ] 7. 伝える
```

## 1. 範囲を決めて読む

- 今日の日付を調べます。
- 頼まれた範囲（タグ・プロジェクト・担当者など）の `tickets/` のチケットを読みます。指定がなければ、未完了のチケットをすべて見ます。

## 2. 洗い出す

次のものを、種類ごとに一覧にします。各チケットには、タイトル・ファイル名・`status`・`start`・`due`・`assignee` を添えます。

- **期限切れ**：`due` が今日より前の未完了
- **長く止まっている**：`status` が `doing` か `waiting` のまま、`start` や `due` から長くたっているもの
- **決まっていない**：`assignee` か `due` が空の未完了
- **親子のずれ**：子の `due` が親の `due` より後、または子がすべて完了しているのに親が未完了
- **片付けていない**：完了してから日がたったもの（アーカイブの候補）

## 3. 案を出す

チケットごとに、直す案を1つ出します。理由がチケットの本文にあれば添えます。分からないこと（新しい期限、担当者）は推測で埋めず、人に聞きます。

例：

```
■ 期限切れ
  1. 見積書を送る（20261019-1512-x7q2_見積書を送る.md）― doing ／ due 2026-10-30 ／ 高橋
     案：期限を延ばす（新しい期限を教えてください）
  2. 議事メモを共有する（20261020-0900-b2c3_議事メモを共有する.md）― todo ／ due 2026-10-21
     案：完了にする（本文に「共有済み」とある）
■ 片付けていない
  3. 請求書を出す（20260930-1000-d4e5_請求書を出す.md）― done ／ done 2026-10-01
     案：アーカイブする
```

## 4. 人が選ぶ

どの案を反映するかを人に確かめます。**確かめる前にチケットを書き換えたり、移したり、消したりしてはいけません。**

## 5. 書き換える

選ばれた案だけを反映します。

- 変えるのは、その項目の行だけです。ほかの行や本文の書式は変えません。
- 完了にするときは、`RULES.md` の「完了にするとき」に従います（`done` に今日の日付、`repeat` があれば次回分を作る）。
- アーカイブは、ファイルを `archive/` に移すだけです（名前も中身も変えない）。子孫があるときは、`RULES.md` の「アーカイブと削除」に従います。
- 削除は行わず、人に任せます（アプリの削除は Windows のごみ箱に移す）。

## 6. 書いた後に見直す

直したチケットごとに、次を見直します。違っていたら直してから、もう一度見直します。

- 変えた項目のほかに、行が変わっていない
- 日付が `YYYY-MM-DD` で、`start` が `due` より後になっていない
- 完了にしたチケットに `done` が入り、`repeat` があれば次回分ができている
- アーカイブしたチケットが `archive/` にあり、`tickets/` に残っていない

## 7. 伝える

変えたチケットと、何を変えたかを人に伝えます。直さなかったものがあれば、それも伝えます。
