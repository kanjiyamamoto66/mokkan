# プロジェクトの入口のノートを作る・直す

入口のノートは、そのプロジェクトについて調べるときに最初に読むノートです。プロジェクトのフォルダの直下に1つ置きます。決まりは `RULES.md` の「ノートの書き方」の「入口のノート」にあります。まだ読んでいなければ、先に読みます。

この手順で使う言葉：

- **入口**：プロジェクトのフォルダの直下の `type: index` のノート
- **知識**：`type: knowledge` のノート
- **記録**：`type: record` のノート

## 進み具合

次のチェックリストを写し、進めながら印を付けます。

```
入口のノートを作る・直す：
- [ ] 1. プロジェクトのノートを読む
- [ ] 2. 入口の案を出す
- [ ] 3. 人が確かめる（確かめるまで書かない）
- [ ] 4. 書く
- [ ] 5. 書いた後に見直す
- [ ] 6. 伝える
```

## 1. プロジェクトのノートを読む

- プロジェクトのフォルダ（その下のフォルダも）のノートを見ます。今の入口があれば、それも読みます。
- 知識は、何について書いてあるか（本文の最初の1〜3行）を読みます。
- 記録は、目的や、まだ知識になっていない話を探すために、新しいものから読みます。

## 2. 入口の案を出す

次の3つの見出しで、入口の中身を出します。今の入口があれば、変えるところだけを出します。

- **目的**：このプロジェクトが何のためのものか。ノートから読み取れなければ、人に聞きます（推測で書かない）。
- **知識の状況**：ナレッジそのものの状態だけを書きます。まだ知識になっていないテーマ、知識に取り込んでいない記録、古くなっているかもしれない知識（`reviewed` が古い、`（要確認` がある）など。決まったことや予定の中身（「見積は来週金曜までに送る」など）は書きません。決まったことは知識のノートに、予定や作業はチケットに書きます。
- **ノートの一覧**：知識を1つずつ、リンクと1行の要約で。記録は並べません。

**プロジェクトの進み具合は書きません。** 何が終わった・何をしている・何が残っているかはチケットだけに持たせます。今の方針や決まりは、入口ではなく知識に書き、一覧からリンクします。

例：

```markdown
## 目的

A社向けの受発注システムの更新。2027年3月の切り替えに向けて、見積から納品までを決める。

## 知識の状況

- 納品の手順はまだ知識になっていない（記録の 2026-10-26 の定例にだけある）
- [見積の決まり](20261001-0900-k1a2_見積の決まり.md) は 2026-10-19 の決定を取り込み済み

## ノートの一覧

- [見積の決まり](20261001-0900-k1a2_見積の決まり.md)：見積の書き方（税込・有効期限）
- [A社の窓口](20261005-1000-c9d8_A社の窓口.md)：担当者と連絡のしかた
```

## 3. 人が確かめる

案を人に確かめます。**確かめる前に入口を作ったり書き換えたりしてはいけません。**

## 4. 書く

- 新しく作るときは、`templates/notes/入口.md` をもとに、プロジェクトのフォルダの直下に作ります（なければ `NOTE_TEMPLATE.md` をもとに `type: index` にする）。ファイル名は `ID_入口.md` などにします。
- 直すときは、変えるところだけを書き換えます。

## 5. 書いた後に見直す

次を見直します。違っていたら直してから、もう一度見直します。

- `type: index` になっていて、プロジェクトのフォルダの直下にある（入口は1つだけ）
- 一覧のリンクの相対パスが、すべて実際の知識のファイルを指している
- プロジェクトのフォルダの知識が、すべて一覧に載っている
- 進み具合（終わった・残っている）を書いていない

## 6. 伝える

作ったか、何を変えたかを人に伝えます。知識に取り込んでいない記録があれば、取り込み（`mokkan-ingesting-knowledge`）を提案して構いません。
