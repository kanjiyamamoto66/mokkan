# ノートからチケットを起こす

mokkan のノートを読み、やることをチケットにする手順です。どの種類のノートからでも起こせます。チケットとノートの形・ID・ファイル名の決まりは、`RULES.md` の「チケットの形」「frontmatterの項目」「ID」「ファイル名」「ノート」の節にあります。まだ読んでいなければ、先に読みます。

この手順で使う言葉：

- **チケット**：`tickets/` の md。1つのやること
- **候補**：チケットにする前の、やることの案
- **ノート**：起こす元の `notes/` の md

## 進み具合

次のチェックリストを写し、進めながら印を付けます。

```
ノートからチケットを起こす：
- [ ] 1. ノートと、すでに作ったチケットを読む
- [ ] 2. 候補を出す
- [ ] 3. 人が選ぶ（選ぶまで作らない）
- [ ] 4. チケットを作る
- [ ] 5. ノートの「宿題」に書き戻す
- [ ] 6. 書いた後に見直す
- [ ] 7. 伝える
```

## 1. ノートと、すでに作ったチケットを読む

- ノートの frontmatter（`id`・`date`・`created`・`tags`）と本文を読みます。「宿題」の見出しがあれば、その項目を中心に読みます。
- `tickets/` と `archive/` から、`source` がこのノートの `id` のチケットを探します。すでにあるやることは、候補から外します（二重に作らない）。
- 人に「文字起こしは読まないで」と言われたら、「文字起こし」の見出しの下は読みません。

## 2. 候補を出す

候補ごとに、タイトル・担当者・期限・根拠を付けて一覧で出します。

- **期限**：日に決まる言い方（「来週金曜」「11月20日」など）だけを、ノートの `date` を基準に `YYYY-MM-DD` にします。`date` が空なら `created` を基準にし、そのことを伝えます。
- **期限が日に決まらない言い方**（「来週まで」「近いうちに」「月内」など）：期限は空にし、根拠に元の言い方を書きます。日付の案を入れたいときも、期限の欄には入れず、「（案：2026-11-13）」のように別に書きます。
- **担当者**：宿題の「（高橋）」や「高橋が送る」のように、はっきり分かるときだけ入れます。分からなければ空にします。推測で埋めません。
- **根拠**：本文の該当する文を短く引用します（文字起こしがあれば、その発言）。
- **候補にしないもの**：雑談、「検討します」のような、やることが決まっていない話。迷うものは、迷っている理由を書いて出します。
- 「宿題」の項目から出した候補には、どの項目かを添えます。

例（入力：議事メモの「宿題」に `- 見積書を送る（高橋）`、本文に「来週金曜までに見積を出します」「資料は来週までに確認します」、`date: 2026-10-19`）：

```
1. 見積書を送る ― 担当：高橋 ／ 期限：2026-10-30
   根拠：「来週金曜までに見積を出します」（宿題の「見積書を送る（高橋）」）
2. 資料を確認する ― 担当：（空） ／ 期限：（空）
   根拠：「資料は来週までに確認します」（日が決まらないので期限は空。案：2026-10-30）
3. 次回の日程を決める ― 担当：（空） ／ 期限：（空）
   根拠：「次回の日程は改めて」 ※迷い：やることか、ただの話か
```

## 3. 人が選ぶ

どの候補を作るか、タイトル・担当者・期限を直すかを人に確かめます。**確かめる前にチケットを作ってはいけません。**

## 4. チケットを作る

選ばれた候補ごとに、`TEMPLATE.md` をもとにチケットを作ります。

- ファイル名は `ID_タイトル.md` にします（後で名前が変わっても、書き戻すリンクが切れないように）。ID は `RULES.md` の決まりで作り、`tickets/`・`archive/`・`notes/` に同じ ID がないことを調べます。
- `source` にノートの `id` を入れます。
- `tags` は、ノートの `tags` を引き継ぎます（人が別のタグを指定したらそれに従う）。ノートがプロジェクトのフォルダ（`notes/案件A/…`）の中にあれば、そのフォルダ名（`案件A`）も足します。`notes/共通/` と `notes/` の直下のノートからのときは足しません。
- 担当者が2人以上なら `assignee: [高橋, 田中]` と書きます。
- 本文の「メモ」に、根拠を短く書きます。

## 5. ノートの「宿題」に書き戻す

ノートに「宿題」の見出しがあるときだけ、該当する項目の行の最後に ` → [ID](相対パス)` を足します。

- 相対パスは、ノートのフォルダの深さに合わせます（`notes/案件A/` のノートなら `../../tickets/ファイル名`）。ファイル名に空白や括弧があるときは、リンク先を `<…>` で囲みます。
- 例：`- 見積書を送る（高橋） → [20261019-1512-x7q2](../../tickets/20261019-1512-x7q2_見積書を送る.md)`
- 該当する項目がなければ、「宿題」の最後に `- タイトル → [ID](相対パス)` の行を足します。
- 「宿題」の見出しがないノートには書き戻しません（チケットの `source` からノートに戻れる）。
- 書き換えるのは「宿題」の行だけです。ほかの部分、とくに「文字起こし」には触れません。

## 6. 書いた後に見直す

作ったチケットごとに、次を見直します。違っていたら直してから、もう一度見直します。

- ファイル名の先頭の ID と、frontmatter の `id` が同じ
- ほかのファイルと ID が重ならない
- `source` がノートの `id`
- frontmatter の項目が `RULES.md` の順番で、値のない項目も行が残っている
- 書き戻したリンクの相対パスが、作ったチケットのファイルを指している

## 7. 伝える

作ったチケットのタイトルとファイル名、書き戻した行を人に伝えます。

ノートに、日時の決まった次の MTG（「次回：12/3 10:00」など）が書いてあれば、その日の時間割（`days/YYYY-MM-DD.md`）に行を足すことも提案します。足すのは人に確かめてからで、書き方は `RULES.md` の「時間割」に従います（`mokkan-planning-days` と同じ形）。日時が決まっていなければ提案しません。記録のノートからだったときは、同じノートを知識のノートに取り込むこと（`mokkan-ingesting-knowledge`）を提案して構いません。
