# 知識のノートを点検する

知識のノートと入口のノートの中身を点検し、直す案を出す手順です。点検の基準は、`RULES.md` の「ノートの書き方」（知識のノート・入口のノート）です。まだ読んでいなければ、先に読みます。

この手順で使う言葉：

- **知識**：`type: knowledge` のノート
- **入口**：プロジェクトのフォルダの直下の `type: index` のノート
- **見つけたこと**：点検で見つけた、直したほうがよいところ

## 進み具合

次のチェックリストを写し、進めながら印を付けます。

```
知識のノートを点検する：
- [ ] 1. 範囲を決めて読む
- [ ] 2. 点検する
- [ ] 3. 見つけたことと直す案を出す
- [ ] 4. 人が選ぶ（選ぶまで書き換えない）
- [ ] 5. 書き換える
- [ ] 6. 書いた後に見直す
- [ ] 7. 伝える
```

## 1. 範囲を決めて読む

- 頼まれたプロジェクト（`notes/案件A/` など）の入口を読み、一覧から知識を読みます。プロジェクトの指定がなければ、どこを見るかを人に聞きます。
- `notes/共通/` の知識も、関係しそうなものは読みます。
- アプリの「点検」の結果を貼られたときは、その項目に出ているノートを読みます。貼られた結果は、点検した後にファイルが変わって古くなっていることがあるので、**項目ごとに今のファイルで調べ直します**。すでに直っている項目は、直っていると伝えます。

## 2. 点検する

次のことを見ます。

- 同じテーマの知識が重なっていないか
- 知識どうしで、記述が食い違っていないか
- 入口の一覧と、実際の知識が合っているか（一覧にない知識、要約が中身と合わない行）
- `reviewed` が古い知識や、`（要確認` `（未確認）` が残っている記述
- 経緯や「以前は〜」が書いてあり、今の正しい状態だけになっていない記述
- 長すぎる知識（目安は1〜2画面）
- 切れたリンク・相対パスがずれたリンク（アプリの「点検」の結果にあるもの）

## 3. 見つけたことと直す案を出す

ノートごとに、見つけたことと直す案を出します。点検の結果は人に伝えるだけで、ファイルには書きません。

| 見つけたこと | 直す案 |
| --- | --- |
| 重なり | 1つにまとめる（残すノートと、消すか要約とリンクだけにするノート） |
| 食い違い | どちらが正しいかを根拠の記録の `date` から示す。分からなければ人に聞く |
| 入口とのずれ | 一覧に足す・消す・要約を書き換える行 |
| 古い・要確認 | 調べて書き換える。調べても分からないものは、分からないと書く |
| 経緯の混ざり | 今の状態だけに書き換える（根拠は記録へのリンクにする） |
| 長すぎる | テーマごとに分ける（分けた先のタイトルと要約） |
| 切れた・ずれたリンク | 今のファイル名への相対パスに直す。リンク先がどこにも見つからなければ、推測で別のファイルに付け替えず、消すか書き換えるかを人に聞く |
| 入口がない | 入口を作る（作り方は `mokkan-writing-project-indexes` と同じ） |

## 4. 人が選ぶ

どの案を反映するかを人に確かめます。**確かめる前にノートを書き換えてはいけません。**

## 5. 書き換える

選ばれた案だけを反映します。書き換えた知識の `reviewed` を今日にし、入口の一覧も合わせて直します。

## 6. 書いた後に見直す

書き換えたノートごとに、次を見直します。違っていたら直してから、もう一度見直します。

- 直したリンクの相対パスが、実際のファイルを指している
- 入口の一覧と、プロジェクトのフォルダの知識が合っている
- 書き換えた知識の `reviewed` が今日になっている

## 7. 伝える

書き換えたノートごとに、何を変えたかを1〜2行で人に伝えます。直さなかった見つけたことがあれば、それも伝えます。
